# 楼层脚本状态

1.99 的账本、身份专属机制和终端领取状态保存在楼层变量的 `_amamiState`，位于 `stat_data` 外：

```text
_amamiState
├─ version: 1
├─ experience       本地真实累计经验与已发奖等级（stat_data 仅显示其投影）
├─ attributeGrowth  成长、手动加点、已发自由点
├─ money            资金收支与任务结算
├─ bank             贷款合同与还款进度
├─ identity         身份 ID（羁绊值直接读取 MVU 派生）
└─ 什亭之匣         第 2 楼助手回复完成后写入 true，供后续楼层和同名世界书条目的 EJS 读取
```

`model.ts`
负责结构及旧根字段迁移。各模块继续独立计算，任务奖励读取路径、经验曲线、成长系数和银行利率均不受本次合并影响。`stat_data.物品系统._天海信用点`
仍是面板余额。

`persistence.ts` 统一继承、恢复与清理，`runtime.ts`
在 MVU 更新事件中接入；手机、战斗、开局和维护脚本通过同一入口读写。旧字段在读取或清理时自动搬入对应分支并移除，新分支已有的值优先，不重复补发奖励。

MVU 的自动写回只复制它自己的字段，不保存额外根字段。运行时在 `BEFORE_MESSAGE_UPDATE` 记录真实提交，等该楼层对应 swipe 的 `stat_data` 写入后，于渲染事件最先保存匹配的 `_amamiState`；其他插件字段保留。新楼层首次显示和手机/维护脚本读取时，缺失的记录只从此前楼层的选中分支继承，不读取未来楼层或同层另一条回复。临时 `parseMessage` 不产生真实提交，维护脚本也不再由临时解析启动延迟的 latest 写入。

找不到有效经验记录时停止经验结算，不从 `stat_data` 猜测已结算等级，不自动执行旧档经验转换。新角色由 `initializeExperience` 明确初始化；明确导入旧档时才调用 `migrateLegacyExperience`。

跟随 MVU 的实际清理结果：保留 `stat_data` 的楼层、0楼及 `snapshot: true` 快照保存完整树；其余楼层改为
`_amamiState: { version: 1, delta: { messageId, changes } }`。每条 swipe 保存相对前楼选中分支的差量，恢复时采用目标 swipe 本身的差量。不会改动正文或 MVU 自己的变量，也不另设保留楼层数。

旧版经济差量和成长清理标记仍可读取。以前已经删除且无法从分支恢复的经验明细不自动重建；新版清理会保留所有分支的变化，包括手动加点明细和身份 ID。所有清理标记也在统一树内，不再新增平行根字段。

身份规则定义放在开局身份数据库，楼层仅保存 `identity.id`。魔装影姬的羁绊值实时读取 `stat_data.关系系统`：当前好感度 ≥80 的不同角色数 ×10，上限 100；别名归并后去重，忽略玩家自身。好感下降、回退楼层或切换 swipe 后自然按该份 MVU 数据重新计算，不保存计量快照或曾经达标清单。新开局提交身份 ID；没有楼层身份的旧档兼容读取聊天身份 ID。改名不影响身份；其他身份不会启用羁绊机制。
