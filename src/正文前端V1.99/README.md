# 正文前端 V1.99 · 性斗（Battle Fuck）集成

V1.99 源自 V1.98 fork，集成正文舞台、同层战斗、SKYLINK 手机和入学档案。

在酒馆助手中导入正式版：

```js
import 'https://cdn.jsdelivr.net/gh/enterprise20020924-web/-@main/dist/正文前端V1.99/index.js';
```

## 构建与使用

GitHub 仓库使用 `pnpm install` 和 `pnpm build` 构建，入口为 `src/正文前端V1.99/index.ts`。战斗、手机、开局和维护脚本的内嵌资源随源码发布。

在完整开发工作区根目录执行 `node tools/build-narrative-v199.mjs`，成品为
`dist/正文前端V1.99/index.js`。命令构建正式战斗页、SKYLINK 手机、测试版开局，同步根目录 3.3.2 本体人物数据、内嵌天赋星盘并打包正文脚本。

酒馆使用此 fork 时只启用一个正文渲染脚本。正文、地图、什亭之匣、星盘、战斗页、手机与入学档案均包含在这个 JS 中；Vue、图标、字体和远程人物图片继续沿用既有网络资源。

此 fork 也内嵌测试版 SKYLINK 学园终端。手机保留可拖动悬浮入口和独立悬浮窗口，桌面／手机端沿用原版适配；主页、状态、资料、背包、技能、关系、任务、商店、地图、CG、后街和设置均保留。手机代码及 CSS 单独构建、压缩进同一正文脚本，样式仅挂到手机自己的 Shadow
Root，不进入正文的全局样式。

手机沿用原有 localStorage、IndexedDB 与后街世界书键，不重置已有配置和聊天记录。本体数值维护程序现随fork内嵌发布，加载时原位更新原维护脚本，保留回复恢复、CG与50级退魔等逻辑，移除旧固定经验升级及等级自动转段位。手机与维护程序都随fork更新。

  `http://127.0.0.1:6621`。原有 V1.98／V1.97 本地导入地址会在 fork 监听期间指向 fork，无需重新配置已连接的酒馆。

## 接入方式

- 正式战斗源码唯一来源为 `src/性斗（Battle Fuck）`，fork 中只保存构建生成的压缩成品和接入模块，不维护第二套战斗逻辑。
- 每场战斗在正文舞台内的独立 iframe 中运行，样式、弹层、文档查询和 BOSS 运行状态独立；战斗内容可在自己的区域中滚动。
- `battle/inline-session.ts` 保存本场变量副本和对手选择，`battle/combat-context.ts`
  连接玩家变量同步与战后续写；`InlineBattleView.vue` 管理模式切换和页面生命周期。
- 通常挂载最近三个 AI 楼层；有已打开战斗的正文楼层也保留挂载，发送后续剧情不会仅因超过三个楼层而销毁该战斗。切换聊天或消息 swipe 时结束相应实例。
- 浏览器整页刷新、源码热更新或宿主重新创建整个消息 DOM 时仍会重新初始化，不保存中途回合。常规正文／战斗切换保留实例。当前完成代码接入与生产构建，未运行实战或浏览器测试。

`_tauritavern/extension-store/amami-image-cache/blobs/images/`，不依赖 WebView 的 HTTP 缓存。数据目录由 TT 接口决定，会跟随 TT 自身的数据位置设置；当前本机目录为
`C:\Users\Administrator\AppData\Roaming\com.tauritavern.client\data\_tauritavern\extension-store\amami-image-cache\blobs\images`。

重启后根据 IndexedDB 中的条目或 TT 本地文件恢复进度，已有图片不会重新下载或逐张重新解码。正文、开局、手机和战斗 iframe 显示已注册图片时，会读取对应的持久文件并复用 Blob
URL；同一文件的 CDN／备用地址共享一份缓存。首次从旧版升级需要把图片内容实际保存一次，会尽量复用已有 HTTP 缓存。显示图片仍需要本机解码，预载完成代表图片已保存，不代表所有图片同时常驻显存。

实现位于
`assets/persistent-image-store.ts`、`assets/persistent-image-cache.ts`、`assets/image-cache-bindings.ts`、`assets/image-preload-*`
和 `opening/AdmissionImagePreload.vue`。隔离浏览器验证工具位于
`tools/persistent-image-cache-preview/`。此前已验证重建服务后恢复本地文件、仅补载缺失项，以及浏览器刷新后离线读取 IndexedDB，记录位于
